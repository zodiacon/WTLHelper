# Breadcrumb

How to build and test is in the root `CLAUDE.md`.

`Breadcrumb`: a breadcrumb bar, as Explorer's address bar (`CBreadcrumbCtrl`, window class `WC_Breadcrumb`), `BRC`-prefixed C-style API (`BRCITEM`, `BRCBUTTON`, `BRCCOLORS`, `BRCN_*`; commctrl owns `BCM_`/`BCN_`; internal names are `Brc*`), GDI-drawn. The app owns the hierarchy: it gives the segments with `SetPath` (each a text, and a name for the path text, which is the names joined with the first separator; an empty name, "This PC", is left out), and the control only says where the user wants to go (`BRCN_NAVIGATE`, with a source: a segment, a child picked, typed, back/forward, up); the app goes there and calls `SetPath` again. A segment's chevron drops down what's under it, which the app adds with `AddChild` while `BRCN_GETCHILDREN` is sent; the child that is the next segment is bold. When the bar narrows the leftmost segments fold into the root chevron, whose list shows them, deepest first, before the root's children (`BrcLayoutBar` in `src/BreadcrumbModel.*`). The drop-downs are one reused popup (`BrcDropList`, `src/BreadcrumbList.cpp`) that doesn't take the activation: a segment's list takes the mouse capture as a menu does (the mouse moving onto another chevron opens its list; a press dragged onto a row and released picks it; a click elsewhere closes it and is eaten), and the control keeps the focus and passes it the keys. Taking the capture sends a `WM_MOUSEMOVE` where the mouse rests, so a move to the same point isn't one (it opened the list under a resting cursor). Clicking the box's empty part edits the path as text in a real `Edit` (`src/BreadcrumbEdit.cpp`, `ALT_MSG_MAP(1)`; `BRCN_BEGINEDIT` may veto or `SetEditText`); Enter sends `BRCNS_TYPED`, which the app may reject (non-zero) to keep editing; the suggestions (`BRCN_GETSUGGESTIONS`, asked once per parent; the history's paths first) drop down in the same popup without the capture, and the history arrow lists the paths typed before (`GetHistory`/`SetHistory`). The control keeps the back/forward list itself: each `SetPath` records its location (the path text, or the string given), and while `Go` sends `BRCNS_BACKFORWARD` the app's `SetPath` moves along the list instead (`BrcHistory::Replace` if the app writes it differently). The keys (`src/BreadcrumbKeys.cpp`) move a focus frame along the enabled parts (it never takes the focus on a click), Enter runs one, Down opens its list, Left/Right in an open list go to the next one; typing starts editing. `CBreadcrumbShell` (`include/BreadcrumbShell.h`) browses the shell's namespace with it: PIDLs as the segments' `lParam`, the location's parsing name for back/forward, the editing name to edit, `SHParseDisplayName` for typed paths; the app passes it the bar's `WM_NOTIFY`. `IShellFolder::CompareIDs` isn't a consistent order, and `std::sort` with it ran past the array (a crash) and took minutes on Gallery: non-file-system folders go through `SafeSort` (a bounded merge sort), file system ones by name. Like LogView it follows WTLHelper's dark mode through `GetSysColor` and the registered `ThemeChanged` message; high contrast uses the system colors over the app's, framing hot and pressed parts in the highlight color (`ForceHighContrast` for testing). Tooltips: one tool moved onto the hot part, naming where Back, Forward and Up go (`SetString` replaces the words). MSAA (`src/BreadcrumbAccessible.cpp`): the bar is a tool bar named "Address: <location>" whose children are its parts (each segment a push button and a drop-down button); an open list is a list whose selected row is reported focused (the control keeps the real focus); default actions are posted (`WM_BRC_ACCACTION`). The model is covered by `BreadcrumbTests`; `BreadcrumbDemo` (a folder browser over the file system, the registry or the shell's namespace, which links WTLHelper on x64) is for checking by hand.
