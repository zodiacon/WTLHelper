# DataGrid

How to build and test is in the root `CLAUDE.md`.

`DataGrid`: a grid of typed columns (`CDataGridCtrl`, window class `WC_DataGrid`), GDI-drawn, `DGV`-prefixed C-style API (`DGVCOLUMN`, `DGVVALUE`, `DGVHITTEST`, `DGVCOLORS`, `DGVN_*` notifications from `DGVN_FIRST` = `0U - 3500U`). Columns are known by IDs the control gives them (`InsertColumn`, from 1, never reused) and kept in `DgColumnSet` with a display order of all of them, hidden ones too; each has a slot, also never reused, where the store keeps its values, so deleting a column only clears its slot (`DgStore::ClearSlot`). Rows are either the store's (`DgStore`, a vector of cells per row, the default) or the app's in virtual mode (`SetVirtual`, `SetRowCount`), which the control asks for with `DGVN_GETDISPINFO` as it paints (`Fetch`) and keeps in `DgCellCache`, trimmed after every paint to the rows around the view and dropped by `RedrawRows`. The view works in rows in view, mapped to rows in the data by `DgRowMap` (the identity for now: sorting and filtering will set an order), while the API, the caret and the notifications use data rows, so they survive sorting.

The window-free model (`src/DataGridModel.*`) mirrors the public constants in its own namespaced enums (`DgType`, `DgColType`, `DgAlign`, `DgColFlag`, `DgHitFlag`) so the tests needn't include ATL; `DataGridCtrl.cpp` `static_assert`s that they agree, so a new value goes in both. `DgLayoutColumns` places the visible columns: fixed ones at their width (DIPs, never under their minimum), fill ones (`DGVCOLUMN::fill`) sharing the width the fixed ones leave by cumulative shares so they add up exactly, each at least its minimum; frozen columns (`SetFrozenColumns`) that would leave no room to scroll the rest are dropped from the right. A column's `left` is unscrolled; `DgLayout::Left` adds the row header and subtracts the horizontal scroll for the columns past the frozen ones, which scroll under them (`ScrollLeft`). Rows scroll whole: `topRow` is a 64-bit row, and `DgScrollMap` scales a top row past `MaxPos` (`0x3FFFFFFF`) onto the 32-bit scroll bar with both ends exact, so billions of rows work (the demo's Data menu has five billion). `DgHitTest` gives the header's dividers priority over the titles (the nearest within the zone, a tie to the later column so a narrow one can still be widened), skipping scrolled columns' dividers that are under the frozen ones; `DgDropIndex` finds where a dragged column goes by the columns' middles. `DgNavigate` moves the caret as Excel does (Ctrl+arrows to the edges, Home/End, Ctrl+Home/End); PgUp/PgDn move the view with the caret, as a list view does.

Formatting (`DgFormat`) goes by the column's type, then the value's: an enum's integer names an item of `pszEnumItems`, a progress column shows a percent of an integer 0-100 or a float 0-1, an integer column rounds a float, a float column shows `decimals` digits, `DGVCF_GROUPDIGITS` groups with the user's separator (`DgNumberFormat`, read from the locale on `WM_SETTINGCHANGE`). Dates are FILETIMEs taken as local time and shown in the user's short date and time (`DgCellText`); `DgFormatDateTime` is the model's ISO fallback, for the tests. Check boxes and progress bars are drawn, not themed parts, so they follow the colors (and dark mode).

Painting (`DataGridPaint.cpp`) goes through a memory DC: the scrolling columns, then the frozen ones over them (filled first, since the scrolled ones run under them), the row numbers (`DGVS_ROWHEADER`, as wide as the row count's digits), the caret's frame (2px in the highlight focused, 1px gray not), then the header in a semi-bold font, with the dragged title following the mouse and a bar where it would go. Colors are read from `GetSysColor` on every paint, blended from the window's colors (grid lines, the header, the caret's row), so WTLHelper's dark mode works with no dependency; `ThemeChanged` (registered by name), `WM_THEMECHANGED` and `WM_SYSCOLORCHANGE` repaint. The scroll bars are the window's own, which dark mode's child theming doesn't reach: `UpdateScrollBarTheme` (on create, those messages and `SetColors`) gives the grid `DarkMode_Explorer` when its background is dark, only when that changes, since `SetWindowTheme` sends `WM_THEMECHANGED` back. `SetColors` overrides any of them (`CLR_DEFAULT`: the system's). High contrast ignores them and uses the system's colors. Sizes are DIPs, scaled with the window's DPI; `WM_DPICHANGED_AFTERPARENT` remakes the fonts and the layout.

The header's mouse (`DataGridHeader.cpp`): a divider drag resizes live (a fill column becomes fixed; `DGVN_COLUMNRESIZED` on release), a double-click fits it to its title and the rows in view (`MeasureColumn`), a title press that moves past `SM_CXDRAG` becomes a column drag (scrolling near the edges; `DGVN_COLUMNMOVED`), otherwise a click (`DGVN_COLUMNCLICK`; non-zero from the app stops the sort it would do). `DGVS_NOCOLUMNRESIZE`/`DGVS_NOCOLUMNREORDER` and the columns' `DGVCF_NORESIZE`/`DGVCF_NOREORDER` stop them. `Relayout` reruns up to three times when a scroll bar showing or hiding resizes the client area (`sizedAgain`).

Cells (`DataGridInput.cpp`): a click selects the cell and moves the caret there (`DGVN_CARETCHANGED`, `DGVN_SELCHANGED`; `SetCaret` sends neither and puts the selection on the caret), a double-click or Enter sends `DGVN_ACTIVATE`, a plain click on a link column's cell `DGVN_LINKCLICK`, a right-click outside the selection selects the cell (inside, it only moves the caret, as in Excel) then `WM_CONTEXTMENU` sends `DGVN_CONTEXTMENU` (from the keyboard: under the caret's cell). Focus without a caret puts it at the top row's first column.

The selection (`DataGridSelection.cpp`, the model's `DgSelection`) is rectangles (`DgRange`) of rows in view and indexes into the visible columns, the last one the one Shift extends from the anchor; the caret is the end that moves (so it follows a drag or Shift+arrows, unlike Excel's active cell). Being in view terms it means nothing once the rows are sorted or the visible columns change: `ApplyOrder` and `Relayout` (when the visible IDs differ from `shownIds`) put it back on the caret's cell, which is kept by data row and ID; fewer rows only clip it (`Clamp`). `DGVSM_CELLS` (the default): a click resets, Shift extends, Ctrl adds a range, a drag extends (with `WM_TIMER` scrolling past the edges, `DgPosFromPoint` clamping the point to the cells in view), the row numbers select whole rows without moving the caret's column (`wholeRows`), the corner and Ctrl+A everything, Shift+Space the caret's row, Ctrl+Space its column. `DGVSM_ROWS`: every range spans the columns, Ctrl+click and Ctrl+Space toggle a row (splitting a range), and the selection may be empty. `DGVSM_SINGLE`: only the caret's cell. A selection of the caret's cell alone isn't shaded (the caret's frame shows it); the rest is a blend of the highlight (`crSelection`), paler without the focus, and their row numbers and (cells mode) titles are tinted. `Copy` (Ctrl+C, Ctrl+Insert; Ctrl+Shift+C with the titles) puts the rows and columns the selection touches, cells outside it empty, on the clipboard as TSV (`DgTsvField` quotes as Excel does) and `HTML Format` (`DgCfHtml` with its byte offsets, UTF-8); past a million cells it beeps and copies nothing.

Sorting: a click on a title goes unsorted, ascending, descending, unsorted (`DgClickSort`), Shift+click adds the column as another key or turns it; `DGVS_NOSORT` or `DGVCF_NOSORT` stop it. `DGVN_SORTCHANGING` (non-zero stops it) and `DGVN_SORTCHANGED` are sent for the user's sorts only (`SetSortKeys` sends nothing). The store's rows are sorted into the row map (`DgSortOrder`: a stable sort of the data rows; numbers and check boxes before dates before text, text in the user's order with digits as numbers (`CompareStringEx`, `SORT_DIGITSASNUMBERS`); empty cells last whichever way). After sorting the caret's row is scrolled into view. Virtual mode only shows the keys (an arrow, and their order when there are several): the app sorts its rows on `DGVN_SORTCHANGED` and calls `RedrawRows`, or stops what it can't do on `DGVN_SORTCHANGING`, as the demo does for all but ID. Inserting or deleting rows sorts again; `SetCell` doesn't (rows don't jump while they're changed), `Resort` does. Sorting runs on the UI thread for now (the plan has it sliced for big stores in phase 4).

Editing (`DataGridEdit.cpp`) is off unless `DGVS_EDITABLE`; `DGVCF_READONLY` locks a column. F2 or a double-click opens an editor with the cell's text (`DgEditText`: numbers ungrouped with every digit that reads back the same, ISO dates), typing a character opens it with that character instead (and then the arrows commit and move, as Excel's Enter mode; F2 in the editor switches to moving in the text). The editor is a child over the cell (`m_Editor`, `ALT_MSG_MAP(1)`): an `Edit` for text, numbers, links and progress (typed: "42%", "42" or "0.5"), a drop-down list for enums, a date picker (`DTS_SHOWNONE` for an empty cell; the user's short date and time format) for dates; check boxes have none: a click on the box, a double-click (a second click) or Space toggles them (Space every selected check box, to the caret's new state), and editable empty ones show an empty box to click. Enter or Tab commit and move (Shift: back), Esc cancels (`DgEditKey`); the focus going elsewhere commits (posted `WM_DGV_ENDEDIT`, after the focus settles), or cancels with a beep if the value can't be kept; a click on the grid with a value that can't be kept does nothing, so the editor stays. Scrolling moves the editor (`PositionEditor` in `ScrollRows`, `ScrollX` and `Relayout`) and closes it, committing, when its cell leaves the view; sorting commits first. An editor nobody changed writes nothing (`dirty`: `EN_CHANGE`, `CBN_SELCHANGE`, `DTN_DATETIMECHANGE`, or typing), so opening and closing one doesn't round a date's fraction of a second or a float's digits. The text is parsed by the column's type (`DgParseValue`: the user's separators, with a no-break space as one; a whole number for integers; enums by name or index; dates as ISO or, through `DgParseUserDate` (`VarDateFromStr`), in the user's format, so what was copied pastes back), then `DGVN_VALIDATE` lets the app change or reject the value; a rejection shows a balloon under the cell (`ShowError`, for five seconds) and keeps the editor. Every change goes through `Apply`: written to the store, or in virtual mode sent to the app as `DGVN_SETCELL` (and the cell's cache dropped), pushed on the undo stack (`DgUndoStack`, a hundred steps, by data row and column ID) and announced with `DGVN_CELLSCHANGED` and its reason. Ctrl+V or Shift+Insert pastes tab-separated text (`DgParseTsv`, Excel's quoting) from the top-left of the selection's last range, or one value into every selected cell (`DgPasteTargets`), skipping read-only cells and values that don't parse or validate (with one beep), as one undo step, and selects what it pasted; Delete clears the selected cells, Shift+Delete or Ctrl+X cuts. Ctrl+Z undoes and Ctrl+Y or Ctrl+Shift+Z redoes, selecting the first cell changed. Inserting or deleting rows (or fewer rows, or deleting a column, or switching modes) clears the undo stack, since its rows' indexes would name other rows; so must the app when it re-orders a virtual grid's rows itself (`ClearUndo`, as the demo does when it reverses them). Edits don't re-sort a sorted store. The editors' colors follow the grid's (`WM_CTLCOLOREDIT`, `WM_CTLCOLORLISTBOX`).

Filtering, sorting and grouping (`DataGridView.cpp`) are one rebuild, `ApplyOrder`, run for any change to them or to the rows: `DgBuildView` filters (each column has at most one `DgFilter`: contains, case ignored, in the shown text; a range of numbers or dates, either end open; or a set of shown texts and blanks), then stable-sorts by the group columns first (ascending, unless a sort key on the column gives its direction) and the sort keys after, then walks the rows into nested groups (`DgGroup`, pre-order, each with its rows' range, the index past its subtree, a key that's its path of values, and the aggregates of the columns that have one, `DGVCOLUMN::aggregate`: sum, average, minimum, maximum, count). `DgFlatten` turns that into the row map's entries, a group's row as `-1 - index` (`DgRowMap::GroupOf`; `ToData` gives -1 for them), skipping closed groups (`collapsed`, by key, so they stay closed when rebuilt). The store's columns that matter are copied into a `DgViewInput` first, so the build reads nothing the UI thread changes: under `BackgroundRows` (100,000) it runs inline, past that on a detached `std::thread` with a cancel flag, the last rows staying up with a "Working..." note until `WM_DGV_VIEWDONE` (matched by `generation`; a newer rebuild cancels the older) shows it and sends `DGVN_VIEWREADY`. Text compares and dates' text are `CompareStringEx` and `DgValueText`, both fine on the worker. A sort with the user's caret scrolls to it when the rows are shown (`ensureCaret`); grouping and filtering start at the top, and a caret whose row is filtered out or closed into a group goes to the first row shown (`Reflatten(from)`; a closed group: the first row after it). Virtual mode keeps and shows the filters (the app filters on `DGVN_FILTERCHANGED`) and doesn't group. A group's row (`PaintGroupRow`) is a band with its open or closed mark, indented by level, "Column: value  N rows" in bold, and each aggregate (`DgAggregateText`: "Σ 1,234", "avg 3.50") in its column's cell; a click on it, anywhere, opens or closes it (`DGVN_GROUPEXPANDED`), and the keys skip such rows (`DgSkipGroupRows`), Ctrl+- closes the caret's group and Ctrl++ opens them all; copying leaves them out. `DGVS_FILTERROW` adds a row under the titles (`DgLayout::titles` is the titles' height, `header` with the filter row; `DgHitTest` gives `FilterRow` there) showing each column's filter (`FilterSummary`) in the accent color, "Filter..." where the mouse is: a click opens an edit box over the cell (`m_FilterEdit`, `ALT_MSG_MAP(2)`) that filters 300 ms after the typing pauses (`FilterTimer`), Tab moves to the next column's, Enter, Esc or leaving closes it. `DGVS_HEADERMENU` puts a button at each title's right (`DGVHT_HEADERBUTTON`, an arrow while the mouse is on the title) with a menu: sort ascending, descending or not, group by the column or stop, clear the filter or all of them, type a filter, and the column's values (`DgDistinctTexts`, the first 50 in the values' order, the store's) to tick and untick: a value filter of the ones left ticked (all ticked again: none); with more values than shown, a click shows only that one. A filtered column's title has a funnel (in the button's place). `DGVN_FILTERCHANGING` and `DGVN_GROUPCHANGED` come with the user's changes only.

Covered by `DataGridTests`, which uses Catch2 (vcpkg: `catch2` for the static triplets, `VcpkgUseStatic`; its own `main` runs `Catch::Session`), the only tests here that do: each `TEST_CASE` has a tag for its part (`[layout]`, `[caret]`, `[format]`, `[data]`, `[selection]`, `[sort]`, `[clipboard]`, `[edit]`, `[view]`, `[find]`, `[state]`), so `DataGridTests.exe "[view]"` runs those and `DataGridTests.exe Undo` one test; `CHECK_STR` and `CHECK_INT` compare wide strings as `std::wstring` and integers of any type as `long long`, and a `CHECK` with `&&` or `||` needs its own parentheses (Catch2 won't take them apart). They cover columns and order, layout with fill, hidden and frozen columns and the filter row, scrolling and the scroll bar's mapping, hit testing, drop places, navigation, formatting, the store, the cache, the row map with groups' rows, points to cells, the selection in each mode, clamping it, the sort clicks, comparing values, sort orders with several keys, TSV, HTML, UTF-8 and the clipboard's HTML format, the selection as a table, parsing every type's text with the user's separators, ISO and the user's dates, the editors' starting text and its round trip, parsing TSV and its round trip with copying, where pasted fields go, the editor's keys, undo, each kind of filter, building views (filtered, sorted, grouped, nested, canceled), flattening them with closed groups, aggregates and their text, distinct values and skipping groups' rows, the new row in the row map, matching text, finding cells (each way, wrapping or not, in a column, the start last, limits and stopping), conditional formats' rules and the looks they give, and the state's round trip with every escape and its rejections. `DataGridDemo` (which links WTLHelper on x64) is for checking by hand: store and virtual data over every column type, frozen columns, the styles, custom colors, a large font, dark mode, the selection modes, copying, sorting (virtual: by ID only), deleting the selected rows, editing (ID read-only, Quantity rejecting negative numbers; virtual mode keeping the changed cells in the demo), the filter row and the titles' menu, grouping by Category and In stock with the quantity's sum and the price's average, a million rows rebuilt on the worker thread, the new row (Edit > New Row; virtual mode keeps what's typed in the rows it adds), finding (Edit > Find, F3), conditional formats (low quantities' rows, high prices, the tools, discontinued notes, in colors for the mode), zebra rows and out-of-stock marks through custom draw, saving and restoring the layout, and a log of the notifications.

The new row (`DGVS_NEWROW`, with `DGVS_EDITABLE`; `DataGridState.cpp`): `DgRowMap::SetNewRow` (set in `Relayout` from the styles) makes one more row in view after all the others, groups' rows included, whose data row is `DgRowMap::NewRow` (-2, `DGV_NEWROW`), so the hit testing, scrolling, navigation and painting take it as a row with no changes; what needs a data row checks `>= 0` (`Fetch` fails, `Copy` skips it), and `DgData::HasCaret` takes the caret on it. It's painted with a star for its number and a hint across it. `CanEditCell` lets its cells be edited (not check boxes: there's no row to toggle yet); a value committed in its editor (`EndEdit`, `adding`) goes through `DGVN_VALIDATE` with the index the row will get, then `AddNewRow` sends `DGVN_ROWADDING` (non-zero stops it), appends a row (the store's, or the virtual count plus one), puts the caret on it (`ensureCaret`, wherever it's sorted) and rebuilds the view, sends `DGVN_ROWADDED`, and the value is written as an undoable edit. Appending moves no row's index, so the undo stack stays. The rows changing under the open editor would end it again (`PositionEditor`): `edit.closing` stops that. An empty value adds nothing.

Finding (`DataGridFind.cpp`): `DgFindCell` walks the rows in view from a cell, across then down (or back), wrapping, every cell once (the start last unless it counts), within a column range, at most `maxRows` rows and until `stop()`; `DgTextMatches` compares the shown text without copies (case ignored with `towlower`, or exact, a part or the whole). `Find` moves the caret and the selection to the cell; `nullptr` repeats the last text (as F3). Ctrl+F (unless `DGVS_NOFINDBOX`) opens a find box over the top right of the rows (`m_FindEdit`, `ALT_MSG_MAP(3)`, `PositionFindBox` in `Relayout`): typing finds from the caret's cell itself (so it stays while it matches) within 150 ms (`TypingBudget`; out of time isn't a miss), shades every matching cell in view in amber (`SetHighlight`), and turns the text red when nothing matches (`findMiss`, `OnCtlColor`); Enter and F3 find the next with no time limit, Shift the one before, Tab back to the cells, Esc closes it and the shading. Cells looked at aren't put in the virtual cache (`Fetch`'s `keep`). A virtual grid asks `DGVN_FINDCELL` first (the app may answer), else looks at `DGV_VIRTUALFINDROWS` (10,000) rows: about a second through `DGVN_GETDISPINFO` (the demo's ten columns, Release); the store looks at all (a million rows' miss: about 4 s).

Conditional formats (`AddFormatRule`, `DgFormatRule`): a column's value against one or two values (`DgCondOp`: comparisons, between, contains, empty), giving text and back colors and bold, to the cell or the whole row. `DgRuleMatches` compares numbers with numbers, dates with dates, text with text case ignored, and text against another kind's shown text (an enum's name); `DgResolveLook` goes through the rules in order, the first to set a color wins. Painting fetches the rules' columns once per row. High contrast ignores them. Custom draw is `NM_CUSTOMDRAW` with `NMDGVCUSTOMDRAW` (`NMCUSTOMDRAW` plus the data row, the column and the colors), as a list view's: prepaint, each data row (`dwItemSpec`: the row in view; its colors), each cell (`CDDS_SUBITEM`: colors in as the rules left them, `CDRF_NEWFONT`, `CDRF_SKIPDEFAULT`, `CDRF_NOTIFYPOSTPAINT`), and postpaint; not the groups' rows or the new row. A cell's back is the row's, a rule's, the find's shading, then the app's; the selection blends over a color that isn't the row's (55%). Dark mode's own subclasses handle `NM_CUSTOMDRAW` by the sender's class, so the grid's go to the app.

The state (`GetState`, `SetState`; `DgSaveState`, `DgLoadState`): one line, `dgv1;cols=id:width[:fN][:h],...;frozen=N;sort=id[d],...;group=id,...;filter=id:c:text` (or `id:r:min:max`, `id:v:blanks:value:...`, values typed as `e`, `t`, `i`, `f` with 17 digits, `b`, `d` ticks), text escaped as `%XXXX` (the separators, `%` and control characters). A key it doesn't know is skipped, anything malformed fails and changes nothing. `SetState` keeps the columns it doesn't name after the others, drops what names columns that are gone, groups only the store, and rebuilds once (`ApplyOrder`); a virtual grid's app sorts and filters by what it reads back.

Accessibility (`DataGridAccessible.cpp`, MSAA): one class, `DgAccessible`, for the table (`ROLE_SYSTEM_TABLE`, the system's client object for its own location and state), its rows in view (`ROLE_SYSTEM_ROW`, "Row N", a group's label with expanded or collapsed, "New row") and their cells (`ROLE_SYSTEM_CELL`: the shown text as name and value, the column's title as description, selected, focused, read-only, checked, off-screen). Each is an object of its own, made when asked for (`get_accChild`, `accNavigate`, `accHitTest`, `get_accFocus` all hand out `IDispatch`es), sharing a `DgAccLink` the grid cuts on `WM_DESTROY`, after which they answer `RPC_E_DISCONNECTED`. The caret's cell is the focus: `MoveCaret` and `WM_SETFOCUS` send `EVENT_OBJECT_FOCUS` with child ID `CaretChild` (`LONG_MAX`), which the table's `get_accChild` turns into that cell. A cell's default action toggles a check box, opens the editor or activates; `put_accValue` writes a value as an edit (validated, undoable; the new row's adds a row). The table's name comes from the system's client object (the window's text or label), never from the window object: with no text, the window object asks the client for its name, which is the table again, without end (a stack overflow found with the demo).
