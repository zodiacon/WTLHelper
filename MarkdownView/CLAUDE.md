# MarkdownView

How to build and test is in the root `CLAUDE.md`.

`MarkdownView`: a markdown viewer (`CMarkdownViewCtrl`, window class `WC_MarkdownView`, `MDV`-prefixed C-style API: `MDVSTYLE`, `MDVCOLORS`, `MDVHEADING`, `MDVN_*`; internal names are `Mdv*`), drawn with Direct2D and DirectWrite: help pages and readmes, with GitHub's extensions and the HTML readmes use (math is shown as its source, Mermaid as a code block, other HTML as its text). The parser is md4c 0.5.2 (MIT), vendored in `src/md4c/` and built with `MD4C_USE_UTF16`, so offsets are UTF-16 positions in the source. md4c's UTF-16 mode had three bugs, patched there and to be kept over an update from upstream: the `X(name)` macro of the HTML block tags took the narrow literal's size (halved lengths: `<h1>`, `<p>`, `<details>` weren't HTML blocks), and `md_build_attribute` and the CDATA check counted characters as bytes in `memcpy`/`memcmp` (garbage after an entity in a link's URL). The model (`src/MarkdownViewModel.*`, `MarkdownViewText.cpp`, `MarkdownViewExport.cpp`) builds a tree of blocks (`MdvBlock`; md4c has no tight list item paragraphs, so the builder makes them) whose leaves hold their inline content as one string (`MdvInline`: the text, an image as U+FFFC, style runs, links, images) with a map back to the source (`MdvSegment`; an entity or a shortcode maps whole), so positions can be kept as source offsets. On top of md4c: GitHub's alerts (`> [!NOTE]` alone on its line), footnotes (md4c doesn't have them, and takes a one-word definition for a link reference definition, so definitions are also found in the source and references are also links whose text is `^label`), emoji shortcodes (a table of common ones), heading anchors (GitHub's slugs, `-1` for duplicates; `<a name>` and `id` too), YAML front matter (skipped, kept in `frontMatter`), and a subset of raw HTML (`MdvTokenizeHtml`): `align` on `p`/`div`/`center`/`h1`-`h6` (a div's alignment reaches the markdown blocks inside it), `img` with `width`/`height`, `a href`, `details`/`summary` (a container over the following blocks until `</details>` or the enclosing block's end), `br`, `hr`, and inline `b i s u code kbd sub sup mark`; other tags are dropped and their text kept, `script` and `style` with their content. Export: plain text, HTML and CF_HTML of the document or a range (`MdvRange` of leaf positions), and the source text of a range (whole lines at its ends). `MdvColumnWidths` sizes table columns as HTML's auto layout; `MdvClassifyUrl` tells anchors, web, mail and file links from `javascript:`/`vbscript:`/`data:`. The view (`src/MarkdownViewCtrl.cpp`, `MarkdownViewPaint.cpp`; its state, with every D2D and DirectWrite resource, is `MdvState` in `src/MarkdownViewData.h`, kept out of the public header) lays the document out as a flow (`src/MarkdownViewLayout.*`, window-free): `MdvFlow::Build` makes a box per leaf (a paragraph, a heading, a code block, a rule, an alert's title, a details' summary; a table is one box) with its indent, padding, margins (collapsed between boxes as CSS's, a container's on its last box), a list item's or footnote's marker on its first box, and the bars of quotes and alerts as spans over their boxes; `Place` stacks them. A box's height is estimated (characters per line) until it comes into view, when `Measure` makes its `IDWriteTextLayout` (cached by block and box kind with the width it was made for; runs become font weights, styles, the code font, smaller sub/sup; links' colors are drawing effects, set at paint time since brushes belong to the render target). `MeasureVisible` keeps the first box shown where it was while the heights above it change, and `Relayout` (a new width, zoom, style, a details toggled) keeps the block at the top. Line spacing is proportional (1.5 of the font size, the extra shared above and below), so a tall inline image doesn't overlap the lines. A format is shared by every layout made from it, so all it has (alignment included, `MdvAlignMiddle`/`MdvAlignCenter`) is in its cache key and it's never changed after: an alert's title once set a shared format's paragraph alignment, and the layouts made from it later (a table's header cells) drew their text 1e7 DIPs down. Tables (`MeasureTable`): a layout per cell, the columns sized by `MdvColumnWidths` from each column's widest word (`DetermineMinWidth`) and unwrapped width; when even the words don't fit, columns keep their unwrapped widths up to 25em and the table scrolls sideways, as GitHub's do. Code blocks don't wrap and are colored by `pfnHighlight`-style `MDVHIGHLIGHTPROC` (`SetHighlighter`; -1 keeps the built-in one) or the built-in lexer (`src/MarkdownViewSyntax.*`, window-free: C/C++, C#, Java, JS/TS, JSON, Python, PowerShell, shell, Rust, Go, SQL, CSS, markup, YAML; colors `MDVCOLORS::crSyntax`); a code block or table wider than its box scrolls sideways (`MdvState::sideways` by block: Shift+wheel, the tilt wheel, a thin bar drawn in the block to drag or page), and the mouse over a code block shows a copy button (CRLF text, a check mark for 1.5 s). Images (`src/MarkdownViewImages.cpp`): local files (relative to `SetBasePath`/`LoadFile`'s folder, `MdvResolvePath`) and `data:` URLs are decoded on one worker thread (`MdvLoader`, shared with the thread so it outlives the window; WIC to premultiplied BGRA, at most 4096 pixels a side) that posts `WM_MDV_IMAGES`; anything else is `MDVN_GETIMAGE` (the app gives an `IStream` or an `HBITMAP` now, or `SetImage` later); an SVG is kept as text and drawn by `ID2D1DeviceContext5::DrawSvgDocument`, which draws no `<text>`, so its texts (`MdvSvgTexts`: positions through `scale()`/`translate()` and the root's viewBox, fill, anchor) are drawn over it with DirectWrite (badges lost their labels). A superscript or a subscript is an inline object (`ShiftedText`) holding its own small layout drawn off the baseline, since DirectWrite has no baseline shift; selection and links still see its range. An image is an inline object sized by its HTML `width`/`height`, else its own size once loaded (a frame until then; one that failed, or that the app has not given, shows its alt text), never wider than the text; when one arrives, the layouts using it (`MdvImageEntry::users`) are made again; a layout with a tall image uses the font's own line spacing, since proportional spacing added a share of the image's height above it. The layout is in DIPs: a DPI change only sets the target's DPI. It follows WTLHelper's dark mode through `GetSysColor` and the registered `ThemeChanged` message (the scroll bar `DarkMode_Explorer`). Selection (`src/MarkdownViewSelection.cpp`) is two `MdvTextPos` (a text leaf, `MdvDocument::TextLeaves` order, and a place in its content), so it runs over paragraphs, code blocks and table cells; `PositionAt` finds the text under a point (a table's cell by its rows and columns, `LeafText` gives a leaf's layout and where it's drawn, a code block's sideways offset included; between boxes, the next text's start), a drag past the view's edges scrolls (`ScrollTimer`), a double click selects a word (`MdvWordAt`), a third click the block, Shift+click extends. The selection is a light shade of the highlight behind the text (`crSelBack`, `crSelBackInactive` without the focus), drawn with `HighlightAll`'s matches (`crFindBack`) before the text; `Copy` (Ctrl+C, `WM_COPY`) puts plain text (`MdvPlainText`, CRLF) and CF_HTML (`MdvHtml`) on the clipboard; `GetSelectedMarkdown` is the source (`MdvSourceRange`). `Find` (`MdvFindNext` from the selection, going round; F3/Shift+F3 repeat it) selects and shows a match (`ShowPosition`: a closed `<details>` opens, a code block scrolls sideways). A press on a link that doesn't become a drag is `MDVN_LINKCLICK` (non-zero: the app's; else a `#link` scrolls and nothing else is opened); the link under the mouse is `MDVN_LINKHOT` and one tooltip tool moved onto it (`MDVS_NOLINKTIPS`); with `MDVS_TASKCLICK` a task box's click is `MDVN_TASKTOGGLE`, which may veto, else the source's character becomes 'x' or ' ' in place (`GetText` has it). `HitTest` (`MDVHT_*`), `MDVN_CONTEXTMENU` (from the keyboard at the selection's end), `MDVN_SELCHANGED` for the user's changes only. Like DiffView it follows WTLHelper's dark mode, and high contrast uses the system colors over the app's (`ForceHighContrast` for testing): no tints, so code blocks, code spans, keys, `<mark>`, the selection and the finds are framed instead of shaded, tables lose their stripes, alerts and syntax are in the text color; images are drawn as they are. Accessibility is out of scope. The model and the flow are covered by `MarkdownViewTests`; `MarkdownViewDemo` (a sample readme whose logo and badges it gives as SVGs through `MDVN_GETIMAGE`, a large document, a contents list that follows the view, an app highlighter, the system's Find dialog, a status bar with the hot link, links to other documents, high contrast drawing, which links WTLHelper on x64) is for checking by hand.
